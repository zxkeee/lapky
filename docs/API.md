# Лапки — склад першої версії, модель даних і контракт API

Автор розділу: Нікіта (аналітик-стратег). Відповідає завданню тижня №1:
«визначити можливості першої версії, описати дані, визначити, як сервер передає інформацію карті й боту».

## 1. Що входить у першу версію (MVP)

| Входить | Не входить (після захисту) |
|---|---|
| Список притулків, сортування за терміновістю | Особистий кабінет притулку |
| Фільтр за 5 категоріями + 4 види корму | Реєстрація користувачів |
| Пошук за назвою / містом / районом / адресою | Онлайн-оплата через сервіс |
| Картка притулку: контакти, соцмережі, реквізити, потреби | Сповіщення про нові потреби |
| Вебкарта з маркерами та фільтрами | Фото тварин |
| Telegram-бот із меню за UX-документом | Багатомовність |
| Зміна даних через адмін-API (токен) | Веб-адмінка (поки — Swagger `/docs`) |

Принцип: **одне джерело правди**. Ні карта, ні бот не мають власних даних — лише читають API.

## 2. Модель даних

### `shelters`

| Поле | Тип | Обов'язкове | Опис |
|---|---|---|---|
| id | int | так | автоматично |
| name | text | так | назва притулку |
| urgency_level | `red` \| `orange` \| `white` \| `green` | так (за замовч. `white`) | терміновість, колір маркера |
| city | text | так | місто |
| district | text | ні | район |
| address | text | так | вулиця, будинок |
| lat, lng | float | так | координати для карти |
| phone | text | ні | телефон |
| contact_person | text | ні | контактна особа |
| social_links | list[text] | ні | соцмережі / сайт |
| requisites | text | ні | IBAN або картка |
| bank | text | ні | назва банку |
| source_url | text | ні | звідки дані (для перевірки, тиждень 6) |
| verified_at | `YYYY-MM-DD` | ні | дата останньої перевірки |
| updated_at | datetime | так | автоматично, оновлюється і при зміні потреб |

### `needs` (одна потреба — один рядок)

| Поле | Тип | Опис |
|---|---|---|
| id | int | автоматично |
| shelter_id | int | притулок (при видаленні притулку потреби видаляються) |
| category | `housing` \| `food` \| `care` \| `finance` \| `volunteer` | категорія |
| subcategory | `kids` \| `adult` \| `sterilized` \| `medical` \| null | **лише для `food`** |
| text | text | що саме потрібно, напр. «Теплі ковдри (20 шт.)» |

Чому потреби — окрема таблиця, а не поле-список: так працює фільтр за категорією одним запитом,
і можна змінити/видалити одну потребу, не переписуючи весь притулок.

Категорія «Фінанси»: притулок потрапляє у фільтр, якщо в нього є реквізити **або** окремий збір (`finance`-потреба).

### Категорії (як у документі Софії)

| key | Назва | Колір |
|---|---|---|
| housing | Проживання | сірий `#8E9196` |
| food | Харчування та здоров'я | коричневий `#8B5A3C` |
| care | Догляд та дозвілля | рожевий `#E07A9B` |
| finance | Фінансова підтримка | жовтий `#E5B800` |
| volunteer | Волонтерство та авто | фіолетовий `#8A5CC7` |

## 3. Контракт API

База: `http://<сервер>:8000`. Формат — JSON, UTF-8. Інтерактивна документація: `/docs`.

### Читання (карта й бот, без авторизації)

`GET /api/meta` — довідники рівнів терміновості й категорій (назви, кольори, емодзі). Клієнти беруть
підписи звідси, щоб у карті й боті вони були однакові.

`GET /api/shelters` — список притулків із потребами.

| Параметр | Значення | За замовч. |
|---|---|---|
| category | housing / food / care / finance / volunteer | — |
| subcategory | kids / adult / sterilized / medical (автоматично означає `category=food`) | — |
| urgency | red / orange / white / green | — |
| q | рядок пошуку | — |
| sort | `urgency` (🔴→🟠→⚪→🟢, далі за назвою) / `name` | `urgency` |

Бот: «Усі притулки» → `sort=urgency`; «Фільтр» → `sort=name` (за вимогою Софії — без сортування за терміновістю).

`GET /api/shelters/{id}` — один притулок. `404`, якщо немає.

Приклад відповіді (скорочено):

```json
{
  "id": 1,
  "name": "Світлі Лапки",
  "urgency_level": "red",
  "city": "Київ", "district": "Солом'янський район", "address": "вул. Лісова, 12",
  "lat": 50.429, "lng": 30.442,
  "phone": "+380 67 123 45 67", "contact_person": "Анна",
  "social_links": ["https://instagram.com/svitli_lapy"],
  "requisites": "UA123456789000000123456789", "bank": "ПриватБанк",
  "source_url": "тестові дані", "verified_at": "2026-10-01",
  "updated_at": "2026-10-02 12:00:00",
  "needs": [
    {"id": 1, "category": "housing", "subcategory": null, "text": "Теплі ковдри (20 шт.)", "updated_at": "..."},
    {"id": 3, "category": "food", "subcategory": "sterilized", "text": "Корм для стерилізованих котів (сухий)", "updated_at": "..."}
  ]
}
```

### Зміна даних (потрібен заголовок `X-Admin-Token`)

| Метод | Шлях | Що робить |
|---|---|---|
| POST | `/api/shelters` | створити притулок (можна одразу з `needs`) |
| PATCH | `/api/shelters/{id}` | змінити поля (напр. лише `urgency_level`) |
| DELETE | `/api/shelters/{id}` | видалити притулок разом із потребами |
| POST | `/api/shelters/{id}/needs` | додати потребу |
| PATCH | `/api/needs/{id}` | змінити потребу |
| DELETE | `/api/needs/{id}` | видалити (закрити) потребу |

### Помилки

| Код | Коли |
|---|---|
| 403 | невірний `X-Admin-Token` |
| 404 | притулок / потребу не знайдено |
| 422 | невалідні дані (немає обов'язкового поля, `subcategory` не для `food`, координати поза межами тощо) |

Бот при недоступності сервера показує «Сервер тимчасово недоступний», карта — підказку перезапустити сервер.
