# 🐾 Лапки — сервіс допомоги притулкам для тварин

Єдиний сервер і база даних, до яких підключені **вебкарта** та **Telegram-бот**.
Змінили потребу в базі — вона однаково з'являється і на карті, і в боті.

```
            ┌──────────────┐
            │  SQLite (БД)  │
            └──────┬───────┘
                   │
         ┌─────────▼─────────┐
         │  FastAPI сервер    │  /api/...   (+ віддає вебкарту на /)
         └─────┬────────┬────┘
               │        │  HTTP / JSON
      ┌────────▼──┐  ┌──▼────────────┐
      │ Вебкарта  │  │ Telegram-бот   │
      │ (Leaflet) │  │ (aiogram 3)    │
      └───────────┘  └────────────────┘
```

## Швидкий старт (локально)

```bash
python -m venv .venv && source .venv/bin/activate    # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env            # вписати BOT_TOKEN і ADMIN_TOKEN

python -m backend.seed          # 10 реальних притулків Києва та області
uvicorn backend.main:app --reload
```

- Вебкарта: http://127.0.0.1:8000
- Документація API (Swagger, можна тицяти запити): http://127.0.0.1:8000/docs

В іншому терміналі:

```bash
python -m bot.main
```

Тести API: `pytest -q`

### Через Docker

```bash
cp .env.example .env   # заповнити
docker compose up --build
```

## Що працює

**Сервер** — список притулків із сортуванням за терміновістю (🔴 → 🟠 → ⚪ → 🟢), фільтр за 5 категоріями
та підкатегоріями корму, пошук (кирилиця без урахування регістру), картка притулку, довідники кольорів/емодзі
(`/api/meta`), адмін-ендпоінти для додавання й зміни притулків і потреб (заголовок `X-Admin-Token`).

**Бот** (за UX-документом Софії) — привітання з кнопкою «Зрозуміло!», головне меню 2×2,
«Усі притулки» з посиланням на карту і списком за терміновістю (по 8 на сторінку), «Фільтр за потребами»
з підменю корму (без сортування за терміновістю — за назвою), картка притулку за шаблоном Блоку Б,
кнопки «Показати на вебкарті / Зв'язатися / Назад до списку», «Як допомогти», «Про проєкт», «Додати притулок».

**Вебкарта** — мінімалістичний монохромний інтерфейс: заголовок одразу каже, скільки притулків потребує
допомоги зараз; легенда терміновості працює як фільтр; вкладки категорій, пошук. Точки кольору терміновості
(критичні — з м'яким пульсом), картка з потребами за категоріями, «Подзвонити», «Маршрут», копіювання IBAN
або донат, джерело й дата перевірки. Посилання `/?shelter=ID` (на нього веде кнопка з бота), `Esc` — назад,
автооновлення раз на хвилину, адаптив під телефон.

## Важливо

- **Дані реальні** — 10 притулків Києва й області з офіційних сайтів і ЗМІ (`backend/seed.py`).
  Джерела й список того, що треба доперевірити, — `docs/DATA_SOURCES.md`.
  Координати частини притулків приблизні; терміновість виставлена командою.
- Кнопки-посилання на карту в боті з'являються лише коли `WEB_URL` — публічна адреса
  (Telegram не приймає `localhost`). Для демо підійде `ngrok http 8000` або `cloudflared tunnel`.
  Поки адреса локальна, бот показує посилання текстом.
- Тексти бота — чернетка Софії (`bot/texts.py`); кольори/емодзі категорій — `backend/constants.py`.
  Обидва місця позначені в документі як «потребує погодження команди», їх легко поміняти.
- Leaflet лежить локально у `web/vendor/` — карта не залежить від CDN.

## Структура

```
backend/   main.py (API) · models.py (валідація) · db.py · schema.sql · constants.py · seed.py
bot/       main.py (хендлери) · ui.py (картка, клавіатури) · texts.py · api.py (клієнт сервера)
web/       index.html (вебкарта), vendor/leaflet
docs/      API.md — склад MVP, модель даних, контракт API
           DATA_SOURCES.md — звідки дані і що перевірити
           TESTING.md — автотести й чекліст ручного тестування
           DEMO.md — сценарій демонстрації на захисті
scripts/   demo_sync.py — «змінили в базі → видно всюди» для демо
tests/     test_api.py
```
